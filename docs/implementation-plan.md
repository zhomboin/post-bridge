# 首期完整实施计划

> 执行人员先阅读本计划和对应阶段计划，再使用 executing-plans 技能按任务推进；需要独立实施或审阅时使用 subagent-driven-development 技能。所有任务使用复选框跟踪，实际完成证据统一进入总体进度。执行状态与验证证据见[总体进度](progress.md)和[验收记录](acceptance.md)；真实平台操作须按授权范围执行。

## 目标、依据与当前起点

交付独立部署的多平台内容发布系统：管理员在中文后台预览分发稿、确认目标平台，服务器持久化执行 CSDN、知乎和小红书的发布任务，提供状态核对、日志及安全的登录验证入口，并与一个 CMS 可靠连接。

依据：[需求规划](requirements.md)、[后台规范](admin-ui.md)、[前端技能要求](frontend-skills.md)和[贡献指南](../AGENTS.md)。需求是范围依据，后台规范是界面依据；本计划说明实施顺序。仓库包含三个应用单元、CSDN 草稿任务接口、测试、CI 及 WSL 本地运行脚本。用户指定优先完成 CSDN 后台草稿链路，详细交付见[总体进度](progress.md)；未完成的全平台、CMS 与上线任务继续按本计划推进。下文涉及的扩展目录和部署产物按对应任务建立。

首期保持单管理员、单 CMS、每个平台一个账号；不增加团队收费、定时发布、AI 改写、批量搬运、自动更新或撤回外站文章。跨平台发布成功必须有分别验证的证据，不能用页面、草稿或模拟结果替代。

## 架构与技术基线

采用一个仓库中的三个独立单元：Go API 管理认证、内容版本、任务和数据；React/TypeScript 后台提供操作界面；Node.js/Playwright 执行器负责结构化内容转换、平台适配和浏览器操作。PostgreSQL 存储任务与业务数据，首期使用数据库任务队列，不额外引入 Redis；Ubuntu systemd 管理 API 与执行器常驻，数据库独立运行，CMS 通过受限服务端接口接入。

前端采用 Vite，并参考 shadcn/ui 的后台布局组织组件；测试采用 Go testing、Vitest、Testing Library 和 Playwright。以上作为实施基线，B01 对官方支持范围、兼容性和许可证进行核验并固定具体版本及锁文件；不使用浮动镜像或自动追随最新版。远程验证采用每账号隔离的无头浏览器，在后台通过已认证代理传输内存画面和受限输入，不开放桌面、VNC 或调试端口。

正式执行器直接调用 Playwright 编程接口，以固定代码定位页面、校验状态并执行操作。Go 后台负责调度、重试与结果存储；生产运行不依赖 AI Agent、大模型服务或模型密钥。Playwright CLI 只用于开发调试和能力验证，开发阶段的 AI 辅助及前端设计技能不进入运行链路。页面发生不兼容变化时停止并报告，由开发人员修复适配器，不能让模型在线猜测点击。

API 是数据库唯一业务写入入口。执行器通过独立内部身份领取任务、上报心跳和结果；领取标识过期后不能修改任务。管理员会话、CMS 来源凭据和执行器凭据分别授权。浏览器目录与临时素材不进入 Git，也不由前端公开目录提供访问。

技术依据：[PostgreSQL 队列式取锁](https://www.postgresql.org/docs/current/sql-select.html)、[Playwright 登录状态](https://playwright.dev/docs/auth)、[Vite](https://vite.dev/guide/)及 [systemd 服务](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html)。平台发布能力仍以目标账号和部署环境实测为准。

## 接口、数据与安全必须共同遵守的规则

- 来源标识与原稿标识组成稳定身份；原稿版本、状态顺序号、内容指纹分别记录。父任务按请求创建，子任务按平台账号拆分，已成功结果不可被其他平台失败覆盖。
- 相同请求标识和内容返回原任务，内容不同报冲突。确认绑定不可变平台稿版本；跨页编辑不能替换，状态变更导致的正式版本递增可在指纹相同时接受。
- API 以事务领取子任务并控制账号占用、租期和领取代次；执行器续期。租期失效要先停止并确认旧执行器退出，临界提交进入核对，不能单凭租期到期再次发文。
- 外站提交前记录提交意图并复查原稿状态与版本。按“未提交／提交已确认／提交不确定”恢复；不确定只能核对或人工确认，禁止自动重发。保留状态检查与外站生效之间仍存在竞争窗口的说明。
- 等待验证释放全局执行槽位，但保留该账号的专用控制归属；人工会话与自动任务不能同时修改同一账号。验证结束先核对外站，再恢复任务。
- 预览正文仅解析内容结构，不执行 MDX 组件；素材限制来源域名、实际内容、跳转、解析后的目标地址、体积和时限。管理员、来源与执行器权限彼此隔离。
- 页面、日志、素材、诊断文件和远程入口分别鉴权；日志全流程脱敏。前端不保存来源密钥，不以隐藏按钮替代服务端授权。

## 测试与执行方式

每项开发先补能复现行为、边界或异常的用例，确认失败原因，再实现并运行受影响范围；配置和文档只做对应静态检查。单次任务可拆成多个小提交，提交前核对相关文档。GitHub CI 承担全量类型检查、单元、集成、模拟端到端及构建，真实平台发布不进入自动 CI。

当前 PowerShell 入口、工具环境和使用方式见[开发说明](development.md)。入口已可执行；命令单独运行，失败立即停止，不使用 Bash 串联语法。

| 当前入口 | 用途 |
| --- | --- |
| scripts/setup.ps1 | 初始化私有配置与本项目数据库 |
| scripts/dev.ps1 | 构建并启动本地后台、API 和执行器 |
| scripts/login-csdn.ps1 | 在 WSLg 隔离窗口人工登录指定账号 |
| scripts/status.ps1、scripts/stop.ps1 | 查看状态、安全关闭本项目服务与登录助手 |
| scripts/test.ps1 | Go 与 Node 测试集入口；日常优先在对应应用选择具体用例 |
| .github/workflows/ci.yml | Linux 上执行全量类型检查、测试、E2E 与构建，不连接真实平台 |

局部验证使用各应用测试工具的文件或名称过滤，只执行改动可能影响的范围；不得用完整集替代必要的目标定位。真实平台验收按单独授权进行，不复用 CI 开关。当前未交付的容器与远程验证入口继续按对应任务实施。

## 交付、风险与计划清理

每个任务通过功能分支和 PR 合并，合并前独立检视需求、代码和相关文档；合并后在真实主分支执行受影响验证，再删除本次分支与 worktree。不能在仍未合并时清理成果。

平台页面变化、账号权限、审核结果不可查询、浏览器资源和 CMS 配合均按任务记录证据与阻塞；任务提交结果不确定时保持待核对。任务记录区分代码完成、本地验证、平台实测和生产验收，不凭估算或模拟勾选真实验收。

每阶段完成后更新[总体进度](progress.md)并链接平台、接口、运维或验收的权威文档。仅本计划及阶段计划属于临时执行文件；全部实施并确认交付后删除本计划和 `docs/plans/`，同时清理索引链接，必要结论保留在权威文档与[版本记录](version.md)。尚未完成时保留未完成步骤和阻塞。
