# 首期剩余工作与验收顺序

[需求](requirements.md)定义首期范围，[总体进度](progress.md)列出当前交付，[验收记录](acceptance.md)保留证据。各阶段计划跟踪剩余关口。真实账号、平台写入及生产变更按明确授权执行。

## 阶段依赖

| 阶段 | 当前基础 | 剩余关口 |
| --- | --- | --- |
| [A 平台能力验证](plans/a-platform-validation.md) | CSDN 文字及单图草稿、指定单篇手工发布，小红书登录及只读实测 | 核对 CSDN 完整审核与素材边界、小红书图文写入和知乎账号能力 |
| [B 独立系统基础](plans/b-system-foundation.md) | 独立后台、用户及账号隔离、持久队列、来源确认和通用只读能力可用 | 补齐多平台分发、完整权限与重启验证，以及生产监测 |
| [C 平台发布闭环](plans/c-platform-publishing.md) | CSDN 草稿与独立发布代码可用。小红书只读与本地图文准备可用 | 各目标平台通过真实素材、提交、结果核对及恢复 |
| [D 外部来源联合验收](plans/d-cms-integration.md) | 固定接口、签名向量和 PostBridge 侧守卫完成本地验证 | 真实调用方实现及共同审阅，先模拟、再对授权 CSDN 目标验收，完整多平台联调等 C 阶段通过 |
| [E 上线运维](plans/e-release-operations.md) | Ubuntu systemd 部署入口、HTTPS 模板、合成安装快照构建与回退验证 | 目标环境、生产容量、监测、备份恢复及安全验收 |

A 阶段继续按目标平台验证。未依赖阻塞平台的 B、C、D 或 E 工作可独立推进。目标平台发布能力须通过各自的 A 和 C 关口。真实调用方的 CSDN 草稿链路可独立联调。完整 D 及生产最终验收等待相应平台闭环。

## 专项任务

- [CSDN 图文与发布计划](plans/csdn-rich-publishing.md)跟踪图片、封面、正式发布和调用方联调。
- [小红书接入方案](xiaohongshu-integration.md)及[实施计划](plans/xiaohongshu-integration.md)跟踪真实非空样例、图文编辑和远端提交。
- [多平台内容转换方案](platform-formatting-design.md)及[实施计划](plans/platform-formatting.md)跟踪目标平台草稿对照、本地保真及格式校验。

## 验收证据对应

| 需求第 12 节 | 主要阶段 | 证据 |
| --- | --- | --- |
| 第 1—5 项 | B、E | 独立部署、管理界面、权限、日志、交互及测试 |
| 第 6—13 项 | A、C、D、E | 各平台真实提交、读回和恢复，跨平台部分失败及常驻运行 |
| 第 14—18 项 | B、C、D | 不可变确认、内容兼容、隐私授权、事件及真实调用方可靠发送 |
| 第 19—23 项 | B、C、E | 账号会话隔离、素材输入、进程清理、监测、备份和恢复 |

当前参数见[后台与内部接口](api.md)、[格式化说明](ai-formatting.md)和[运维](operations.md)。生产容量和运行上限在目标环境验证。开发逐步命令和服务器操作分别见[本地开发](development.md)及[Ubuntu 部署](ubuntu-deployment.md)。

交付时通过功能分支和 PR 检视。项目完成并确认验收后，将必要结论保留在手册、验收和版本记录，删除已完成的详细计划并更新引用。
