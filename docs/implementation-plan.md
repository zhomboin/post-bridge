## 目标、依据与当前起点

交付独立部署的多平台内容发布系统：管理员在中文后台预览分发稿、确认目标平台，服务器持久化执行 CSDN、知乎和小红书的发布任务，提供状态核对、日志及安全的登录验证入口，并对任意获批调用方开放固定接口。

依据：[需求规划](requirements.md)、[外部接入总体方案](cms-integration.md)、[后台规范](admin-ui.md)、[前端技能要求](frontend-skills.md)和[贡献指南](../AGENTS.md)。需求是范围依据，后台规范是界面依据；本计划说明实施顺序。仓库包含 API、后台、平台执行器和可选排版服务四个应用单元、CSDN 草稿与账号文章只读接口、PostBridge 侧来源接入、测试、CI 及 WSL/Ubuntu 运行脚本。用户指定优先完成 CSDN 后台草稿链路，详细交付见[总体进度](progress.md)；来源文字草稿子范围已实现并本地验证；未完成的全平台、真实调用方连接与上线任务继续按本计划推进。下文涉及的扩展目录和部署产物按对应任务建立。

首期支持多用户、每用户同平台多个独占账号和固定协议外部调用方；不增加团队收费、定时发布、无来源依据的 AI 扩写、批量搬运、自动更新或撤回外站文章。跨平台发布成功必须有分别验证的证据，不能用页面、草稿或模拟结果替代。

## 架构与技术基线

采用一个仓库中的独立应用单元：Go API 管理认证、内容版本、任务和数据；React/TypeScript 后台提供操作界面；Node.js/Playwright 执行器负责结构化内容转换、平台适配和浏览器操作。可选 formatter 负责 Markdown 保护校验与固定模板卡片渲染，DeepSeek 调用和格式化队列由 API 管理。PostgreSQL 存储任务与业务数据，首期使用数据库任务队列，不额外引入 Redis；Ubuntu systemd 管理 API 与执行器常驻，数据库独立运行，外部调用方通过固定受限接口接入。

前端采用 Vite，并参考 shadcn/ui 的后台布局组织组件；测试采用 Go testing、Vitest、Testing Library 和 Playwright。以上作为实施基线，B01 对官方支持范围、兼容性和许可证进行核验并固定具体版本及锁文件；不使用浮动镜像或自动追随最新版。远程验证采用每账号隔离的无头浏览器，在后台通过已认证代理传输内存画面和受限输入，不开放桌面、VNC 或调试端口。

正式执行器直接调用 Playwright 编程接口，以固定代码定位页面、校验状态并执行操作。Go 后台负责调度、重试与结果存储；平台执行不依赖 AI Agent 或模型密钥；授权原稿可通过可选 DeepSeek 服务准备平台稿。Playwright CLI 只用于开发调试和能力验证，开发阶段的 AI 辅助及前端设计技能不进入运行链路。页面发生不兼容变化时停止并报告，由开发人员修复适配器，不能让模型在线猜测点击。

API 是数据库唯一业务写入入口。执行器通过独立内部身份领取任务、上报心跳和结果；领取标识过期后不能修改任务。本站用户会话、外部应用凭据和执行器凭据分别授权。跨服务器或内网接入先由 PostBridge 登记调用应用，受邀注册、审批、签发与激活后逐请求认证；来源、环境、接收服务及权限独立绑定，停用和撤销立即阻断后续业务，不以网络位置代替身份。浏览器目录与临时素材不进入 Git，也不由前端公开目录提供访问。

技术依据：[PostgreSQL 队列式取锁](https://www.postgresql.org/docs/current/sql-select.html)、[Playwright 登录状态](https://playwright.dev/docs/auth)、[Vite](https://vite.dev/guide/)及 [systemd 服务](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html)。平台发布能力仍以目标账号和部署环境实测为准。

## 接口、数据与安全必须共同遵守的规则

- 来源标识与原稿标识组成稳定身份；原稿版本、状态顺序号、内容指纹分别记录。父任务按请求创建，子任务按平台账号拆分，已成功结果不可被其他平台失败覆盖。
- 相同请求标识和内容返回原任务，内容不同报冲突。确认绑定不可变平台稿版本；跨页编辑不能替换，提交版本和状态序列必须与已确认准备稿一致，变化时重新准备确认。
- API 以事务领取子任务并控制账号占用、租期和领取代次；执行器续期。租期失效要先停止并确认旧执行器退出，临界提交进入核对，不能单凭租期到期再次发文。
- 外站提交前记录提交意图并复查本地快照授权与已收到来源状态。按“未提交／提交已确认／提交不确定”恢复；不确定只能核对或人工确认，禁止自动重发。保留状态检查与外站生效之间仍存在竞争窗口的说明。
- 等待验证释放全局执行槽位，但保留该账号的专用控制归属；人工会话与自动任务不能同时修改同一账号。验证结束先核对外站，再恢复任务。
- 预览正文仅解析内容结构，不执行 MDX 组件；素材限制来源域名、实际内容、跳转、解析后的目标地址、体积和时限。管理员、来源与执行器权限彼此隔离。
- 页面、日志、素材、诊断文件和远程入口分别鉴权；日志全流程脱敏。前端不保存来源密钥，不以隐藏按钮替代服务端授权。

## 测试与执行方式

## 交付、风险与计划清理

每个任务通过功能分支和 PR 合并，合并前独立检视需求、代码和相关文档；合并后在真实主分支执行受影响验证，再删除本次分支与 worktree。不能在仍未合并时清理成果。

平台页面变化、账号权限、审核结果不可查询、浏览器资源和 真实调用方配合均按任务记录证据与阻塞；任务提交结果不确定时保持待核对。任务记录区分代码完成、本地验证、平台实测和生产验收，不凭估算或模拟勾选真实验收。

每阶段完成后更新[总体进度](progress.md)并链接平台、接口、运维或验收的权威文档。仅本计划及阶段计划属于临时执行文件；全部实施并确认交付后删除本计划和 `docs/plans/`，同时清理索引链接，必要结论保留在权威文档与[版本记录](version.md)。尚未完成时保留未完成步骤和阻塞。
