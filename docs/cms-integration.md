# CMS 主入口接入方案

## 1. 范围与状态

采用 CMS 主动提交、PostBridge 独立执行。用户在 CMS 编辑、选平台并确认分发，在 PostBridge 预览与调整平台稿、处理账号验证和异常。CMS 轮询摘要，首期不新增分发结果回调。

本文是待实施设计，以下接口、字段和状态均为拟新增契约，不表示已可调用。D01 将其固定到拟建的 contracts/cms.openapi.yaml 并经双方审阅。本轮只更新 PostBridge 文档，不改代码、数据库或 CMS 仓库。

当前 PostBridge 正式接口仅开放单 CSDN 账号的文字 Markdown 草稿任务，已有持久队列、账号互斥、恢复及只读核对。指定单篇公开提交已验证，后台自动公开发布、图片、来源认证、分发稿和多平台父子任务仍待实施。CMS 已有 MDX、文章修订、发布、下架及私有状态，尚无本次接入功能。

依据：[需求](requirements.md)、[现有 API](api.md)、[总体进度](progress.md)、[总计划](implementation-plan.md)及 [D 阶段计划](plans/d-cms-integration.md)。完整首期仍含三个平台，文字草稿联调不替代公开发布或生产验收。

## 2. 双方职责

| 范围 | CMS | PostBridge |
| --- | --- | --- |
| 内容 | 原稿、修订、私有状态、自有博客发布 | 明确授权的快照与平台稿 |
| 平台 | 展示账号摘要与能力 | 第三方账号、登录、验证、适配和上传 |
| 任务 | 保存选择、可靠投递、查询摘要 | 队列、子任务、恢复、核对和日志 |
| 页面 | 编辑、发布确认、分发摘要 | 平台稿预览与确认、详情及异常处理 |
| 运维 | CMS 数据库及博客链路 | 独立服务、数据库权限、浏览器目录及资源限制 |

不共享数据库、后台登录密钥、管理员会话或第三方凭据。平台稿修改不回写原稿。CMS 代码和文档在 CMS 仓库通过独立 PR 实施，本仓库负责通用契约、分发端及联调要求。

## 3. 操作流程

接入前先按第 5.3 节完成两向调用平台的注册、审批、凭据配置和激活；未完成不能调用业务接口或执行真实分发。此为一次接入流程，之后每次请求仍需认证。

1. CMS 保存原稿，发布确认默认只发自有博客，第三方平台由用户主动勾选。
2. CMS 后端查询目标能力。用户选平台并请求预览后，才授权发送本次草稿快照；私有文章禁止发送。准备稿不能产生外站写入。
3. 用户跳转 PostBridge 独立后台预览、调整并确认平台稿；不嵌入完整编辑器，不在链接中携带密钥或正文。
4. CMS 后端查询准备结果取得确认修订及指纹，不相信浏览器回传的“已确认”标记。
5. CMS 发布事务锁定原稿、核对确认内容，原子保存站内发布及待发送记录。内容改变则重新预览，事务提交后才调用远端。
6. PostBridge 持久接收后快速返回分发标识，按平台账号建立子任务，服务器异步执行。关闭页面不影响投递和执行。
7. CMS 经自身后端轮询摘要；页面隐藏、离开或退出登录停止轮询，失败退避。登录、验证码和未知结果在 PostBridge 处理。
8. PostBridge 首次可能产生外站副作用的写入前检查来源，最终公开提交前再次检查；来源不允许或不可确认时不继续写入。

CMS 当前编辑器先保存再调用发布接口，不能只在前端追加分发调用。发布、确认内容校验及待发送记录须在服务端同一事务完成，防止另一页面的修改被意外发布。

| 情况 | 必须行为 |
| --- | --- |
| 远端不可用但已有有效确认稿 | 自有博客可发布，分发保留待发送 |
| 未完成预览或确认已过期 | 自有博客可独立发布；第三方意图保留待预览或待重新确认，恢复后不自动发布 |
| 远端接收后响应丢失 | 同标识查询或重投，复用原任务 |
| 平台要求登录、验证码 | 等待用户，不消耗普通网络重试预算 |
| 外站可能已接受操作 | 先只读核对，不按普通失败重新发文 |
| 某平台失败 | 保留其他平台成功结果，分别处理 |

## 4. 数据与确认

接口字段使用下划线形式，由连接器映射 CMS 现有字段。

| 字段 | 规则 |
| --- | --- |
| client_id、key_id | 接收方批准的调用应用身份与密钥版本，绑定环境、接收服务及来源权限，不由正文自报 |
| source_id、article_id | 来源加 CMS 稳定 articleId 组成身份，标题、slug 和链接只展示 |
| source_version | CMS 修订，预览与正式发布版本分别记录 |
| state_seq | 按原稿递增的状态顺序，独立于文章版本，删除后保留最小记录 |
| snapshot、content_fingerprint | 筛选后的标题、摘要、正文、格式、标签、封面、素材引用和可选原文链接及其指纹 |
| authorization_id、expires_at | 本次准备授权与期限，撤销和私有状态立即使其失效 |
| preparation_id | 绑定来源内容及目标账号的一次准备稿 |
| targets、operation | 每个目标绑定平台、账号及操作；save_draft 表示保存草稿，publish 表示公开提交，禁止执行端自行升级操作 |
| draft_revision_ids、confirmation_fingerprint | 不可变平台稿修订和确认集合指纹，覆盖平台、账号、operation 及平台稿内容 |
| request_id、event_id | 分发意图和生命周期事件的稳定标识，重投不变，不能代替 state_seq |
| distribution_id、children | 父任务与平台账号子任务 |
| remote_id、remote_url | 经结果确认的外站关联，不凭按钮点击或请求发送认定成功 |

来源指纹按固定字段集合的规范化 UTF-8 表示计算 SHA-256，不含状态、修订号、更新时间和短期下载地址。D01 用双方共同样例固定顺序、空值、换行、标签与素材规则；素材绑定稳定资源标识及内容校验值，更新访问授权不能替换内容。PostBridge 独立验证，不直接信任调用者声明。

CMS 发布导致版本递增时，来源指纹相同且状态、授权有效，可接受正式版本与预览版本不同。正文、素材或平台稿变化必须新建修订并重新确认，另一页面不能替换已确认稿。原文链接若写入平台正文，须在预览中确定；发布后才产生的链接只能作为展示元数据附加。

准备、确认、正式请求和 CMS 来源授权检查都必须绑定逐目标 operation。改变账号、平台或操作须重新确认；草稿授权不能用于公开提交。未实现或未获授权的公开操作应明确拒绝，不能回退成草稿后报告公开发布成功。

正式接收后冻结内容。既有公开文章也能主动预览分发，但须检查同原稿与目标账号已有副本，不允许用新 request_id 绕过去重。再次新建需展示重复风险并重新确认，自动更新、自动撤回不在首期。

## 5. 拟新增接口

### 5.1 CMS 调用 PostBridge

来源接口独立于当前管理员 /api/jobs 与执行器接口。以下路径在 D01 冻结后实施。

| 方法与路径 | 请求重点 | 返回与行为 |
| --- | --- | --- |
| GET /api/integrations/v1/targets | 认证确定来源 | 平台、稳定账号标识、连接状态、检查时间、可用操作和内容限制，无凭据 |
| POST /api/integrations/v1/preparations | request_id、原稿身份、版本、state_seq、授权、快照、指纹及逐目标账号与 operation | 新建 201，重复返回原准备稿；含 preparation_id、期限、预览入口、逐平台问题；无外站写入 |
| GET /api/integrations/v1/preparations/{id} | 来源认证 | 当前修订、校验问题、确认状态、draft_revision_ids、confirmation_fingerprint 与期限 |
| POST /api/integrations/v1/distributions | request_id、原稿身份、正式版本、state_seq、来源指纹、准备标识、确认集合及逐目标账号与 operation | 新建 202，重复返回原分发；来源已发布且授权、确认有效才接收 |
| GET /api/integrations/v1/distributions/{id} | 来源认证 | 父子任务、执行及外站状态、最后核对时间、错误码、待处理事项与链接 |
| GET /api/integrations/v1/distributions?request_id={id} | 来源认证及稳定请求标识 | 查询是否接收；查询异常不能作为重新创建任务的理由 |
| POST /api/integrations/v1/source-events | event_id、原稿身份、state_seq、版本、类型、当前状态、授权及适用指纹 | 事务保存处理，返回是否应用；重复、旧事件不再次生效，同标识不同载荷冲突；无正文 |

准备与正式请求分别按来源及 request_id 去重，同标识不同载荷返回 409。同一确认稿不得更换请求标识重复分发。准备响应丢失可重投原请求。

预览的读取、编辑和确认使用 PostBridge 管理员会话。CMS 服务端重新查询确认结果；回跳地址限定登记白名单，来源凭据及普通跳转链接不能代替管理员登录。

### 5.2 PostBridge 调用 CMS

| 方法与路径 | 请求重点 | 返回与行为 |
| --- | --- | --- |
| GET /api/v1/integrations/postbridge/articles/{id}/distribution-state | 来源身份、待检查授权、准备稿标识及目标账号与 operation | 原稿身份、版本、state_seq、status、指纹、授权有效性及允许的目标账号和 operation；删除返回明确状态，不含正文 |
| GET /api/v1/integrations/postbridge/assets/{id}/download | 原稿及授权绑定的素材标识 | 只提供本次允许的资源，不跨文章访问；跳转仍检查目标 |

状态接口实时读权威数据、禁止缓存，不使用公开博客 API 替代。删除、授权失效禁止执行；超时、认证失败或无法校验响应时暂停，不依赖缓存继续。

文字子范围可先拒绝图片；启用图片须共同交付下载授权、真实类型和大小校验、平台上传与清理，不复用管理员下载凭据。限制登记来源、协议、DNS 目标、实际连接、重定向及耗时，不开放任意地址抓取。

### 5.3 跨网络部署与调用方注册

CMS 与 PostBridge 可以分布在不同服务器、不同内网，通过各自稳定的 HTTPS 入口通信。每个接收服务维护调用应用登记，默认拒绝未注册、未审批、未激活或凭据失效的业务请求；同内网、来源 IP、域名及应用名称都不能代替认证。IP 白名单、VPN 或双向 TLS 可按部署条件叠加，不作为唯一身份依据。

本节约束服务间接入接口；CMS 公开博客接口和用户后台登录继续使用各自既有权限模型，不能用接入凭据替代后台用户身份。

采用受邀注册和管理员审批，先登记调用方，再凭登记身份逐请求认证。首期不开放匿名自助启用，也不建设统一登录中心；应用身份与用户后台登录、原稿预览授权分别管理。后续其他服务复用这一登记模型，每个接收方单独批准调用关系，不因在另一平台注册就自动互信。

| 步骤 | 规则 |
| --- | --- |
| 发出邀请 | 接收方管理员在受保护后台创建限时、单次使用的邀请，预先限定环境、来源和最大权限；邀请只能申请登记，不能访问业务接口 |
| 平台注册 | 调用平台服务端携邀请提交应用名称、环境、请求的来源与权限、固定服务地址；原子消耗邀请并记录待审批申请，不自动抓取申请地址 |
| 审核与签发 | 管理员核对真实调用平台、接收服务与地址，批准权限不得超过邀请上限；签发 client_id、key_id 和随机 client_secret，应用仍待激活 |
| 安全配置 | secret 只在受保护签发环节显示一次，通过管理员控制的安全方式配置到调用服务；注册响应、普通查询、日志和跳转链接均不返回 secret |
| 验证并启用 | 调用方用新凭据签名请求固定激活接口，证明持有凭据；只有审批已通过、凭据有效且验证成功才进入可用状态 |
| 正常访问 | 每次业务请求重新校验登记状态、有效凭据、请求签名、接口权限与资源归属；注册或激活成功不是永久通行凭证 |
| 轮换、停用和撤销 | 轮换由接收方管理员授权，新密钥先完成持有证明才生效，新旧凭据仅在有限交接期并存；停用拒绝业务，撤销或泄露处置立即拒绝旧凭据，重新接入需重新授权 |

登记信息至少包含 client_id、应用名称、调用方向、环境、接收服务标识、绑定 source_id、接口权限、允许账号及 operation、固定服务和素材地址、限流额度、有效期、审批人及状态。key_id 标识具体密钥版本，不等于应用身份。来源绑定和权限由接收方批准，不能采用请求正文自报的来源或权限。

应用状态区分待审批、待激活、可用、暂停、拒绝与撤销；未激活只允许完成凭据验证，拒绝和撤销不能由调用方自行恢复。凭据另行记录有效期与待激活、有效、交接、过期、撤销状态；应用可用也必须存在当前有效凭据。修改来源、权限、环境、接收服务或出站地址需重新审批，不能通过业务请求更新。各环境和两向调用使用不同凭据。

| 调用方向 | 在哪里注册 | 最小授权 |
| --- | --- | --- |
| CMS → PostBridge | CMS 作为调用应用在 PostBridge 登记 | 读取目标、准备及查询稿件、提交及查询分发、发送本来源事件；按账号和 operation 再限制 |
| PostBridge → CMS | PostBridge 作为调用应用在 CMS 独立登记 | 仅读取已授权原稿状态及对应素材，不拥有后台文章编辑、管理员登录或全库读取权限 |

双向登记分别审批和撤销，不共用一组 secret。反向注册及状态检查未完成时，可以进行模拟开发，不能执行依赖来源复查的真实外站写入。

拟新增注册与管理接口如下，均待 D01 冻结。PostBridge 管理接口使用现有管理员会话、CSRF 与来源校验；CMS 对应管理入口使用其自身管理员认证，不复用 CMS 登录密钥。

| 接收方与接口 | 认证和权限 | 行为 |
| --- | --- | --- |
| PostBridge：POST /api/integration-invitations | 管理员 | 创建受限邀请，仅签发时显示邀请值；列表不返回秘密 |
| PostBridge：POST /api/integrations/v1/registrations | 请求头中的有效一次性邀请 | 提交申请返回 registration_id 和待审批状态，无业务权限，不返回凭据 |
| PostBridge：GET /api/integration-registrations | 管理员 | 查看申请，隐去凭据与邀请值 |
| PostBridge：POST /api/integration-registrations/{id}/approve 或 /reject | 管理员 | 审核；批准后创建待激活应用与凭据，签发时安全交付一次 |
| PostBridge：POST /api/integrations/v1/clients/self/activate | 已审批应用的待激活密钥签名 | 验证并激活本密钥，首把密钥成功才启用应用；轮换不改变权限，不能恢复暂停或撤销身份 |
| PostBridge：POST /api/integration-clients/{id}/rotate、/suspend、/resume、/revoke | 管理员 | 轮换、暂停或撤销并审计；暂停恢复也须管理员重新核对后操作 |
| CMS：POST /api/v1/integrations/postbridge/registrations | CMS 管理员签发的一次性邀请 | 接收 PostBridge 调用申请，待审批，无业务权限 |
| CMS：POST /api/v1/integrations/postbridge/clients/self/activate | CMS 已审批应用的待激活密钥签名 | 同样验证首把或轮换密钥，不能恢复暂停或撤销身份 |
| CMS：管理员保护的调用应用管理入口 | CMS 自身管理员认证 | 邀请、查看、审批、签发、轮换、暂停与撤销；准确路径在 CMS PR 固定 |

注册入口虽无需既有应用身份，也必须持邀请且受 HTTPS、请求大小和速率限制；无邀请或邀请过期不能注册，邀请原子单次消费，响应丢失不允许重复建申请，管理员可查询并重新安全交付结果。健康接口最多返回最小就绪状态，不返回应用和注册信息。

所有业务读取、列表、状态及素材接口都要求已激活调用方，不能只保护写接口。管理员、来源和执行器路由隔离，公网代理不转发执行器控制、数据库或浏览器调试端口。

### 5.4 逐请求认证与错误

保留 HMAC-SHA256 签名，并按注册记录选择固定算法及密钥；不接受调用方自选算法或任意密钥地址。签名覆盖 client_id、key_id、环境、接收服务标识、HTTP 方法、外部 HTTPS 目标域与路径及查询、正文摘要、时间戳和一次性标识。D01 采用 RFC 9421 的 HTTP 消息签名机制固定覆盖项、头字段与序列化样例，不自创模糊的字符串拼接规则。

注册仅接受受限邀请，激活仅接受已审批身份的待激活密钥，二者是受控的接入前置入口，不能作为普通业务鉴权例外复用。

业务接收端按以下顺序校验：登记及应用状态 → 接收服务、环境和有效密钥 → 签名、正文完整性、时间窗口及一次性标识 → 接口权限、source_id、账号、operation 与资源归属 → 原稿授权及业务幂等。时间偏差初始上限为五分钟；防重放记录按应用与密钥共享保存至少十分钟，跨实例、重启和轮换不能清空仍有效的记录，存储不可用时拒绝业务请求。D01 固定具体边界，E 在实际服务器验收时钟同步。

重投更新签名、时间戳和一次性标识，业务 request_id、event_id 保持不变。代理必须保留可验证的外部请求目标，应用只信任登记代理提供的转发信息；不能依靠客户端伪造的 Host、转发头或来源 IP 通过认证。请求凭据不能放在 URL，不向其他域名转发签名或 secret。

HMAC 验签端需要可恢复的密钥，不能仅保存 secret 哈希；使用仓库外密钥管理或受控加密存储，解密密钥独立保管。邀请仅保存哈希及用途、期限和消费状态；秘密不进入数据库明文字段、Git、前端持久存储、普通日志、错误或备份明文。注册、审批、签发、激活、权限修改、轮换和拒绝请求均记录脱敏审计。

认证撤销以服务端登记为准，不能仅靠长时间缓存。在业务请求入口和每次新的外站写入前，按任务冻结目标复核当前应用状态、有效凭据及接口、来源、账号、operation 权限；身份失效或权限缩减时暂停相关任务，不沿用接收时的权限。因撤销或缩权暂停的任务，即使后来重新授予权限也须用户重新确认，恢复原任务而非更换标识新建副本；授权持续有效的正常密钥轮换不改变任务身份。已开始操作仍可在有效执行器权限下只读核对，不能因客户端失效而盲目重发。CMS 反向认证失效时无法确认原稿，相关写入同样暂停。恢复须管理员重新授权，不能把撤销的旧身份直接重新启用。数据库回滚或灾难恢复后，恢复出的调用应用默认暂停，管理员核对独立保存的撤销记录并重新签发、激活新凭据后才放行；无法确认最新撤销或防重放状态时禁止直接使用备份中的旧凭据。

| 响应 | 处理 |
| --- | --- |
| 400 | 格式或字段错误，拒绝未知字段，不重投原错误载荷 |
| 401 | 缺失或无效凭据、未启用身份、过期、验签或防重放失败，返回通用认证失败，不泄露应用是否存在 |
| 403 | 身份有效但缺少接口、来源、账号或操作权限；停止原请求并提示管理员 |
| 404 | 本来源资源不存在，跨来源资源同样不可见 |
| 409 | 幂等、内容、确认或副本冲突，以稳定错误码区分 |
| 410 | 原稿授权或准备稿过期、撤销，不自动发布；调用方凭据失效仍按认证失败处理 |
| 413、422 | 超限或内容不兼容，预览阶段指出 |
| 429、503、超时 | 有限退避并遵守 Retry-After，接收不确定先查询或同标识重投，认证设施故障不得放行 |

错误只含稳定 code、可展示 message 与关联标识，不含正文、密钥、邀请、下载授权或原始平台响应。响应禁止共享缓存，日志脱敏。D01 固定大小、速率、查询范围及去重期限，不能未经核验照搬草稿限制。

HTTPS 与逐端点访问控制依据 [OWASP REST 安全指南](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)；签名算法、消息覆盖与防重放依据 [RFC 9421](https://www.rfc-editor.org/rfc/rfc9421.html)。注册审批、权限和停用流程是本项目的接入设计，仍需实现与验收。


## 6. 可靠投递与生命周期

CMS 在发布、下架、转私有、内容改变、删除及撤销授权的本地事务中保存待发送记录，后台发送器独立于页面，重启后继续。自动尝试耗尽仍保留意图及人工恢复入口。去重保留至少覆盖投递恢复与核对周期，清理正文不删除必要去重记录。

PostBridge 按来源及原稿维护最新 state_seq，事件去重与任务处理同事务完成，旧事件不覆盖新状态。正式接收也检查已知序号和实时来源状态，迟到请求不能恢复撤销授权。CMS 已过期或内容改变的待发送项转为待处理。

| 变化 | 无外站副作用 | 已开始外站写入或已提交 |
| --- | --- | --- |
| 内容改变 | 暂停，重新预览 | 停止新增写入，核对副本，不自动覆盖 |
| 下架、私有、删除或撤销 | 取消，清理无用准备稿、快照与素材 | 停止后续操作并核对，保留最小关联和人工入口 |
| 仅状态版本变化且内容相同 | 按最新状态与授权判断 | 不推断外站成功或撤回 |

清理保留进行中、待核对所需的受保护最小数据，不先删除证据。未确认预览默认 24 小时过期；正式接收后按提交快照保留策略处理，不随准备稿到期失效。具体期限沿用总计划并在运维落实。

来源检查与外站操作无法原子完成，仍有短暂竞争窗口，须测试检查后撤销、提交后断网等交错情况。已生效副本不能凭 CMS 状态认定撤回。

CMS 分开展示投递状态、平台执行、外站状态和最后确认时间。草稿成功只显示草稿已保存；审核不可读显示已提交、审核未知；无证据不显示已公开。

CMS 数据库发布、Rendering 页面与索引更新、第三方分发分别验收。自有博客链路由 CMS 与 Rendering 维护。关机后继续执行需常驻服务器，同机 WSL 不代替该验收。

## 8. 实施顺序

| 顺序 | 对应任务 | 交付关口 |
| --- | --- | --- |
| 1 | D01 | 双方审阅方案，先固定注册、审批、激活、双向权限及撤销，再冻结业务接口、签名、指纹、限制和共同样例 |
| 2 | B04—B06 | 先交付并验证两向应用注册、凭据及认证，再实现准备稿、父子任务、去重与实时检查；模拟 CMS 和平台验证 |
| 3 | D02、D03 | CMS 发布事务、待发送与选择，双方生命周期和提交前复查；共同通过才允许真实外站写入 |
| 4 | D04 模拟范围 | 验证断网、丢响应、重启、部分成功、双页编辑、过期和撤销，不计为真实发布通过 |
| 5 | C01—C04、D04 CSDN 子范围 | 文字草稿先联调，结构化转换、素材和公开提交分别补齐验收 |
| 6 | C05—C07、D04、E | 逐平台验知乎、小红书，C07 后完成完整 D04，常驻与生产按 E 验收 |

D01 的定义可先于 B04—B06 实现完成，接口整体可用验收仍依赖这些能力，避免实现和契约互相等待。D02 与 D03 可分开开发，真实任务须共同通过。CSDN 子范围不能关闭完整三平台 D04。

两仓库分别功能分支及 PR，合并前独立审阅，合并后验证再清理。日常本地只测受影响范围，CI 全量检查且不访问真实账号。本轮只检查文档差异、链接、编码、范围与一致性，不运行业务测试。

## 9. 联调验收

- [ ] 未注册、无邀请、重复邀请、待审批、未激活、身份伪造和停用客户端均不能访问业务接口。
- [ ] 双向凭据、环境及接收服务隔离；自报来源、越权账号、操作升级、过期及撤销不能绕过校验。
- [ ] 接收后缩减来源、账号或 operation 权限会阻止排队任务的新写入；重新授权不自动恢复，用户确认后仍沿用原任务，正常密钥轮换不新建副本。
- [ ] 密钥轮换交接、跨实例及重启防重放、时钟偏差、代理目标保持和认证设施不可用按拒绝或暂停处理。
- [ ] 不同内网经 HTTPS 完成注册和双向调用；无需访问数据库、worker 或调试端口，日志、配置和签发流程不泄露秘密。
- [ ] 契约共同样例一致，越权、重放、未知字段和冲突被拒绝。
- [ ] 私有及未授权草稿不外传，预览无外站写入，确认绑定内容、账号及操作；草稿授权不能升级公开提交。
- [ ] 仅状态版本变化可通过，正文变化、跨页编辑及过期确认被阻止。
- [ ] 发布与待发送原子提交，断网、丢响应和重启不丢意图、不重复建任务。
- [ ] 重复乱序事件、迟到提交、检查后撤销及来源不可达按规则处理。
- [ ] 部分成功、登录等待和未知核对不触发成功平台重发。
- [ ] 素材按文章授权，更新访问不替换内容，下载上传边界有效。
- [ ] 草稿、公开提交、审核及公开阅读各有证据，摘要附最后确认时间。
- [ ] 常驻环境用户离线仍执行，两仓库各自完成 PR、文档及临时资源清理。

全部保持待验收。方案落档不表示机器契约冻结、CMS 改造、平台接入或生产上线完成；结果统一进入[总体进度](progress.md)与[验收记录](acceptance.md)。
