# A：平台能力验证实施计划

> 执行人员使用 executing-plans 按下列复选步骤推进；需要独立审阅时使用 subagent-driven-development。依据[总计划](../implementation-plan.md)和[需求](../requirements.md)，本阶段不提前承诺三平台可用或交付时间。

## 目标与通过条件

在计划部署环境验证三个目标账号的真实发布方式、编辑能力、登录验证及结果识别，明确后续实现依据。真实登录、公开测试文章及外站清理必须逐项取得明确授权；编写本计划不代表取得该授权。

## A01：测试授权和环境边界

前置：确认计划部署主机可提供隔离环境。

拟建文件：`docs/platform-capabilities.md`、`docs/acceptance.md`；环境探测记录放入上述文档，凭据和原始敏感证据保存在仓库之外。

- [ ] 记录三个目标账号的所有者、允许的平台、测试文章、公开范围、验证方式及清理责任；未授权的平台保持阻塞。
- [ ] 核实目标主机系统、浏览器依赖、可用内存、磁盘、网络和远程验证入口；先测真实页面打开与浏览器退出，不只检查端口。
- [x] 定义统一验证清单：资格、官方接口权限、内容输入、图片上传、必填字段、提交证据、审核识别和外站链接。
- [ ] 准备不含私有内容的标题、长文、代码、图片、表格及公式样例，明确哪些样例适合小红书图文。
- [x] 更新平台验证状态与授权缺口，不提交账号登录状态、验证码或原始登录截图。

通过条件：每个平台的授权状态与环境准备可核查；未满足项列出责任与影响，不继续真实操作。

## A02：CSDN 能力验证

前置：A01 中 CSDN 已授权。拟维护：`docs/platform-capabilities.md` 的 CSDN 章节与 `docs/acceptance.md`。

- [ ] 核实目标账号是否具备官方发布接口权限；无可用接口时验证服务器浏览器方式。
- [ ] 在目标环境完成官方登录，测试会话保存、重启读取及失效识别，不通过粘贴 Cookie 建立流程。
- [ ] 使用授权样例验证标题、正文、代码、图片、分类和必要发布字段，记录实际限制。
- [ ] 明确区分上传、保存草稿、接受提交、审核中和已公开，记录可取得的文章标识、链接及证据时间。
- [ ] 按授权清理外站测试内容、关闭临时浏览器并记录结论；不将人工操作成功当作自动化适配完成。

通过条件：明确可实施的发布入口和证据采集方式，无法自动识别的状态及阻塞有记录。

## A03：知乎能力验证

前置：A01 中知乎已授权。拟维护：`docs/platform-capabilities.md` 的知乎章节与 `docs/acceptance.md`。

- [ ] 核实目标账号的文章发布资格和接口能力，确定官方接口或浏览器路径。
- [ ] 验证登录、重新登录、需要用户验证及会话重启行为。
- [ ] 检查图片、代码、表格、公式、话题、编辑器输入与发布确认步骤，保留内容转换边界。
- [ ] 验证平台接受提交与审核结果的识别方式，无法查询时记录“状态未知”的显示要求。
- [ ] 按授权清理测试内容与临时进程，记录目标环境和实际账号支持的能力。

通过条件：文章发布、内容兼容性和状态证据均有结论，未验证内容保持待验。

## A04：小红书能力验证

前置：A01 中小红书已授权。拟维护：`docs/platform-capabilities.md` 的小红书章节与 `docs/acceptance.md`。

- [ ] 核实目标账号在官方页面支持的图文发布类型、授权权限及必要资格。
- [ ] 验证登录、短信或扫码处理、会话隔离与重新进入方式。
- [ ] 测试独立标题、精简正文、封面、配图数量顺序与话题；记录实际字数、素材限制，不默认截断长文。
- [ ] 验证提交后的审核状态、文章身份和外站链接获取方式；不能识别时明确未知。
- [ ] 清理授权测试内容和临时资源，记录无法转换时必须先编辑平台稿的条件。

通过条件：授权账号的真实图文能力已确认；不以打开发布页面或仅生成草稿替代验证。

## A05：收敛可实现范围

前置：A02—A04 均有结论，允许结论为阻塞，但不允许没有证据。

拟建：`docs/architecture.md`；维护：`docs/platform-capabilities.md`、`docs/progress.md`。

- [ ] 汇总各平台发布路径、登录成本、必填字段、内容限制、审核可见性和故障核对方式。
- [ ] 将已确认路径映射到平台适配器接口，明确哪些结果可自动确认、哪些只能人工核对。
- [ ] 记录 Go API、后台、执行器、数据库与远程浏览器的职责；验证独立部署和拆迁条件。
- [ ] 平台不能满足要求时提交证据与受影响范围，由用户决定调整；禁止自行降级为人工复制或取消平台。
- [ ] 更新总体进度和下一阶段进入条件，完成独立文档检视后通过 PR 合入。

阶段通过：三平台路线可执行且关键授权与环境问题已解决。未通过时可以推进不依赖阻塞平台的工作，但不得把未通过阶段记为完成。
