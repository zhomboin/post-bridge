# D：CMS 对接实施计划

> 执行人员使用 executing-plans 按任务推进，独立审阅使用 subagent-driven-development。依据[总计划](../implementation-plan.md)和[需求](../requirements.md)。本仓库交付通用契约、接入测试和分发端；CMS 代码在 CMS 仓库单独通过 PR 实施。

## D01：契约核验与联调准备

前置：B04、B05、B06；可先用模拟平台开始，真实最终验收等待 C07。

拟维护：`contracts/cms.openapi.yaml`、`docs/cms-integration.md`；拟建：`tests/integration/cms-contract.test.ts`、`tests/fixtures/cms-events/`。CMS 侧具体文件路径由 CMS 实施人员在实际仓库核对后记录在接入文档，不能凭空假设其内部结构。

- [ ] 确认 CMS 仓库、实施责任、测试地址和来源身份，核对六项操作：发布目标、准备稿、正式提交、查询摘要、状态通知及执行前检查。
- [ ] 固定身份、版本、顺序号、指纹、不可变平台稿版本、账号选择、请求标识、错误与过期规则，校验契约可由两端一致消费。
- [ ] 以共同夹具验证合法请求、重复内容、同标识冲突、未知字段处理和来源越权，契约变动需两端同时审阅。
- [ ] 确定预览授权、正式发布状态递增、素材访问、凭据轮换与连接失败行为，禁止共享 CMS 登录密钥。
- [ ] 建立联调数据和日志关联标识，敏感素材、私有草稿和真实凭据不进入示例。

通过条件：两端接口边界可测试，CMS 真实文件定位、责任和必要前置明确；缺少 CMS 工作区时交付连接器任务说明但不声称改造完成。

## D02：CMS 发布选择与可靠投递

前置：D01，需在 CMS 项目中实施对应更改。

本仓库拟建：`tests/integration/cms-delivery.test.ts`、`tests/fixtures/cms-server.ts`；CMS 拟修改发布确认页面、发布事务服务、待发送记录及发送后台任务，准确路径以 D01 确认结果为准。

- [ ] 测试第三方平台默认不勾选、只发自有博客、主动预览授权和用户确认版本不一致。
- [ ] CMS 服务端过滤快照字段，前端通过本系统预览入口编辑平台稿，保存确认的平台稿版本和内容指纹。
- [ ] CMS 在同一数据库事务保存站内发布与待发送记录，事务成功后再调用分发接口；不会因远端不可用回滚已成功的博客发布。
- [ ] 使用稳定请求标识重试，网络中断或接收响应丢失时查询已有结果，不另造重复请求；待发送状态向用户可见。
- [ ] 接入摘要轮询和后台任务详情入口，恢复后送达已保留的分发意图；不另加分发结果回调体系。

通过条件：提交、断网和恢复均有可靠持久化证据；CMS 项目 PR 与本项目联调记录互相链接，不跨库直接读表。

## D03：生命周期通知与提交前复查

前置：D01、B04—B06、C03。

本仓库拟建：`apps/api/internal/sources/events.go`、`apps/api/internal/jobs/source_guard.go`、`tests/integration/source-lifecycle.test.ts`；CMS 拟修改原稿状态事务及受认证状态查询接口。

- [ ] 测试重复、乱序、旧版本、事件号与内容版本不相同、通知丢失后补发以及不可达状态检查。
- [ ] CMS 在状态变化的本地事务可靠保存下架、设私有和删除事件；分发端按来源和原稿的单调序号处理，重复事件幂等，旧事件不覆盖新状态。
- [ ] 内容改变时暂停未提交任务并要求重新预览；下架、私有或删除取消未提交任务并清理对应授权快照和素材。
- [ ] 执行器外站提交前经 API 查询当前来源状态、版本及指纹；无法确认允许分发时暂停，不能依赖缓存标记继续。
- [ ] 保留已经提交的副本结果和人工处理链接，不自动更新、撤回或重新创建；显式新建要说明重复风险并重新确认。
- [ ] 通过事件与点击提交交错测试说明仍存在的竞争窗口，实际外站副本以核对结果为准。

测试定位：`apps/api/internal/sources/events_test.go`、`apps/api/internal/jobs/source_guard_test.go`。通过条件：没有“原稿已私有但队列仍盲目提交”或“旧通知覆盖新状态”的确定性缺陷。

## D04：CMS 与分发系统联合验收

前置：D02、D03、C07。拟建：`tests/e2e/cms-publishing.spec.ts`；维护：`docs/cms-integration.md`、`docs/acceptance.md`、`docs/progress.md`。

- [ ] 在模拟环境自动验证站内发布成功但远端断网、响应丢失、重复投递、部分平台成功和 CMS 页面关闭。
- [ ] 验证预览后正文变化、仅状态版本变化、双页面编辑、撤销授权和草稿未正式发布，确保确认内容不会被替换。
- [ ] 联合验证来源凭据隔离、素材边界、通知乱序、凭据轮换与恢复后查询摘要。
- [ ] 获得真实链路授权后逐平台验证“CMS 选平台→预览确认→站内发布→服务器自动执行→状态与日志”；关闭用户电脑不影响执行。
- [ ] 在两仓库分别完成 PR 检视、受影响验证及文档更新，记录外站实际状态和未完成事项。

阶段通过：CMS 仍可独立发布自有博客，分发意图可靠保存并恢复，用户可查看准确的各平台结果与日志。
