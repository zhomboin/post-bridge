# D：CMS 对接实施计划

> 使用 writing-plans 整理任务，实施使用 executing-plans，独立审阅使用 subagent-driven-development。依据[接入方案](../cms-integration.md)、[总计划](../implementation-plan.md)和[需求](../requirements.md)。CMS 为主入口，两仓库各自通过 PR 实施，本轮仅完成方案文档。

## D01：契约冻结与联调准备

定义工作可先于 B04—B06 实现；完整接口验收依赖 B04—B06。先用模拟 CMS、模拟平台，真实完整验收等待 C07。

维护 docs/cms-integration.md；拟建 contracts/cms.openapi.yaml、tests/integration/cms-contract.test.ts、tests/fixtures/cms-events/。CMS 现有文件定位和改造责任见接入方案第 7 节，不记录机器专属地址。

- [x] 明确 CMS 主入口、PostBridge 预览与异常入口、双端责任和现有 CMS 源码位置。
- [x] 整理接入方案，列出拟新增接口、确认与生命周期规则、改造范围和实施顺序。
- [ ] 双方先冻结受邀注册、审批、凭据签发、激活、权限、环境及接收服务绑定、轮换与撤销契约；未启用身份不能调用业务读写。
- [ ] 双方审阅并冻结业务机器契约；覆盖目标、准备及确认查询、正式提交、标识查询、摘要、事件、来源检查与素材授权。
- [ ] 固定逐目标 operation，贯穿准备、确认指纹、正式提交及来源授权检查；草稿不能升级为公开提交，未支持操作明确拒绝。
- [ ] 固定签名规范、防重放窗口、轮换规则、来源权限、指纹规范、错误码、大小与速率、有效期及去重保留期限。
- [ ] 以共同样例测试正常、重复、同标识冲突、未知字段、来源越权、版本与事件顺序分离、过期和撤销；实现代码不得与机器契约漂移。
- [ ] 登记私有联调配置与日志关联标识，凭据、真实文章、素材及地址不进入示例或提交。

通过条件：机器契约经双方审阅并可测试。方案落档不等于 D01 全部完成，也不代表来源接口可用。

## D02：CMS 发布选择与可靠投递

前置：D01 契约冻结；实现依赖 B04—B06。可与 D03 分别开发，但真实外站写入必须共同通过。

拟建 tests/integration/cms-delivery.test.ts、tests/fixtures/cms-server.ts。CMS 发布页面、文章服务、SQL、迁移及连接器分别在 CMS 仓库改造，文件定位见接入方案第 7 节。

- [ ] 第三方平台默认不选，支持只发自有博客；仅用户主动请求预览后发送允许外传的快照。
- [ ] 跳转 PostBridge 预览和确认，CMS 服务端查询确认集合；不相信浏览器回参，不传管理员或来源密钥。
- [ ] CMS 在同一事务锁定并核对原稿内容、完成站内发布和保存待发送；正文变化要求重预览，纯状态版本递增按内容指纹判断。
- [ ] 发送器在事务提交后可靠投递，保持稳定请求标识；响应丢失先查询或同标识重投，重启、断网和尝试耗尽不丢意图。
- [ ] 未完成预览、过期或撤销的分发转为待处理，自有博客仍可独立发布；服务恢复不能未经确认自动外发。
- [ ] CMS 经自身后端轮询摘要并跳转详情，不增加结果回调体系；隐藏、离开和退出登录停止轮询，错误退避。
- [ ] 既有公开文章分发也检查已有副本；显式新建需确认重复风险，不用新请求标识绕过去重。

通过条件：事务原子性、断网恢复、去重、确认一致性与页面关闭均有模拟证据，CMS PR 与 PostBridge 联调记录互相引用。

## D03：生命周期、素材授权与写入前复查

前置：D01、B04—B06；外站边界接入依赖 C03，图片启用依赖 C02。与 D02 一起构成真实执行关口。

拟建 apps/api/internal/sources/events.go、apps/api/internal/jobs/source_guard.go、tests/integration/source-lifecycle.test.ts；CMS 增加状态事务、授权、删除最小记录及受限检查和素材接口。

- [ ] CMS 在内容修改、下架、转私有、删除和撤销授权的业务事务中保存事件，按原稿维护单调 state_seq。
- [ ] 接收端事务去重并处理任务，旧事件不覆盖新状态；测试重复、乱序、同标识冲突、补发和迟到正式提交。
- [ ] 内容改变暂停并要求重预览；失去授权取消后续写入，清理无用准备稿与素材，保留待核对必需的最小受保护数据。
- [ ] API 实时检查 CMS 当前状态、版本、指纹和授权，执行器首次外站写入前及最终公开提交前均受检查约束；不可确认则暂停。
- [ ] 启用图片时实现原稿绑定素材授权、真实内容校验、地址限制、平台上传和清理；文字子范围拒绝未支持素材。
- [ ] 已开始外站写入或提交不确定先核对，不自动重建、更新或撤回副本；保留实际状态和人工入口。
- [ ] 覆盖检查后撤销、写入和通知交错、删除后查询及来源不可达，明确不能消除的竞争窗口。

测试定位：apps/api/internal/sources/events_test.go、apps/api/internal/jobs/source_guard_test.go 及来源生命周期集成测试。

通过条件：无“已私有仍依赖缓存继续提交”“旧通知恢复授权”或“清理核对依据后盲目重发”等确定性缺陷。

## D04：分层联合验收

模拟验收依赖 D02、D03 及模拟平台；CSDN 草稿联调仅为子范围。真实公开验收依赖对应平台转换、上传、提交和核对能力；完整 D04 必须等待 C07，不用单平台关闭首期任务。

拟建 tests/e2e/cms-publishing.spec.ts；维护 docs/cms-integration.md、docs/acceptance.md、docs/progress.md。

- [ ] 模拟验证站内发布后远端断网、接收后丢响应、重启、重复请求、部分成功和关闭 CMS 页面。
- [ ] 验证仅状态版本变化、正文变化、双页编辑、未正式发布、未预览、过期及撤销授权。
- [ ] 联合验证注册审批与激活、双向凭据、环境和接收服务隔离、跨实例重放、过期、停用、撤销及轮换，认证设施不可用不得放行。
- [ ] 验证任务排队后移除来源、账号或缩减 operation 权限，新写入被阻止；重新授权后必须用户确认并恢复原任务，正常密钥轮换不重复建任务。
- [ ] 在不同内网经 HTTPS 联调，检查代理外部目标、时钟、受限出站和最小端口；来源与素材边界、事件乱序、迟到提交及执行前检查通过。
- [ ] 按授权完成 CSDN 文字草稿接入，结果只记草稿，不声称自动公开发布通过。
- [ ] 对具备能力且已授权的平台分别验证公开提交、审核与公开阅读，保留不可验证或未知状态。
- [ ] C07 后完成三平台完整联合验收；在常驻服务器验证用户关机后继续执行，WSL 本机验证不替代。
- [ ] 两仓库各自完成 PR 检视、受影响验证、文档同步及临时资源清理，生产结果与本地结果分开登记。

阶段通过：CMS 可独立发布，分发意图不丢失，各平台结果准确，全部关口都有对应证据。
