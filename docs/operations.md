# CSDN 草稿后台运维

## 运行方式与边界

提供 WSL 本地入口及[Ubuntu 无桌面部署入口](ubuntu-deployment.md)。服务器 API 与执行器由 systemd 前台常驻，使用独立服务用户、私有配置与持久浏览器目录；数据库独立管理，Nginx 提供同站点 HTTPS。目标服务器安装、证书和真实平台验证需分别验收，不能将本地合成测试视为生产已上线。

数据库、管理员会话与执行器使用独立权限。执行器不接收数据库连接和管理员密码。管理写请求校验会话、CSRF 和站点来源，内部领取使用独立密钥；不要将内部接口暴露到公网。

## 停止与恢复

- 停止先关闭登录助手，再通知执行器关闭浏览器，再关闭 API，最后停止本项目私有数据库。启动器按 PID、启动代次及完整参数核对归属，拒绝误杀其他进程，不接管系统的 5432 服务。
- 浏览器步骤默认 20 秒，单任务最多 3 分钟。任务领取有 60 秒租期，每 15 秒续期；失效领取不能再上报。普通账号任务串行执行，浏览器目录还使用本地互斥锁。
- 未开始外站操作的网络故障最多安全重试三次，退避 5、20、60 秒；手动重试共用预算。登录恢复和只读核对单独处理。
- 打开新编辑器就可能产生自动草稿。失租、超时或崩溃后延迟 20 秒自动只读核对，每个写入阶段最多 4 轮，间隔 20 秒；重启不重置预算。执行器取得专属浏览器锁并关闭恢复页面，防止旧页面自动保存。
- 填写标题后确认并等待官方页面同步，再保存草稿；发送前再次检查原生保存请求中的标题。标题不一致的请求会被阻断，任务转入只读核对，不盲目重写已有草稿。
- 没有 ID 时自动读取原生管理页草稿列表接口的全部分页，核对账号、草稿状态、标题和正文；数字 ID 为可选兜底。唯一完整匹配才成功，连续两次完整空结果才能在 5 秒后自动重试原任务，共用最多 3 次写入重试预算。取消后只读，不恢复写入。
- 接口请求失败、分页不全、字段变化均不能证明草稿不存在；重复匹配或残稿明确报冲突。4 轮读取耗尽则明确失败，未知结果继续限制该账号写入，但允许再次只读核对。人工结束为可选处理，保留外站内容，不声称保存成功或已撤回。
- 人工结束必须不存在有效领取，且原执行器近期确认浏览器空闲、专属目录可用。若浏览器或互斥锁残留，应先核对原执行器与同目录浏览器确已退出，再由维护人员处理该专属锁；禁止删除整个账号目录或终止无关浏览器。

登录过期时在账号页开始远程登录。当前任务结束后执行器暂停领取新任务，确认认证内容可见后，以无头浏览器提供内存画面、扫码、输入、点击和拖动；确认指定账号后自动恢复需要登录且未取消的任务。认证页启动最多尝试三次页面加载，空白或断连不会进入可操作状态；仍未加载时关闭浏览器并提示页面加载失败。该恢复仅发生在验证开始前，不重新发送短信或提交登录，也不恢复等待任务。扫码使用平台原生二维码创建与轮询；短信表单可使用明确的手机号、验证码填写入口，也可通过“下一输入框”在认证窗口内循环聚焦；隐藏和背景输入不参与切换。画面与输入排队不会终止登录，跳转期间身份暂不可读时继续检查；只有指定后台来源确认身份且没有可见登录提示才恢复任务。远程入口绑定发起者的管理员会话，最长十分钟，六十秒无画面或输入后关闭；退出后台、结束或会话失效会撤销，失败撤销有限重试并保留隔离。画面和输入不落盘、不写日志。

本地登录助手保留为可选入口，不与执行器同时操作目录。禁止索取平台密码、导出 Cookie 或复用个人浏览器目录。异常停止后的目录锁仅在原进程和浏览器已证明退出时恢复，未知锁不自动删除。

## 文章只读同步

文章页的同步操作排队执行，和草稿操作共用账号锁；未知草稿结果阻塞写任务时仍允许只读同步。一次读取最多 2000 条，完整分页核对后原子替换本地快照。登录失效等待人工登录，失败保留旧数据，不将不完整列表当作空账号。

只读浏览器仅允许受限域名的读取和指定正文读取接口，阻止编辑器自动保存及其他写请求。正文只按已同步数字 ID 读取；账号身份、任务绑定、领取有效期和当前快照归属都通过才接收结果。正文不放入任务或日志，缓存最长 30 天；同步成功失效旧正文，详情可重新读取。

## 日志与保留

处理记录以对象的一次提交为一行，保留全部日志入口；处理详情的事件顺序和状态图不受列表时间筛选或日志分页限制。

实际处理前后内容存入独立快照，仅管理员可按需读取并禁止缓存。文章标题、正文来自编辑器或平台实读，账号状态在检查事务中记录；缺失或超限显示未采集，空值不能视作未采集。快照遵循任务正文的 30 天保留及未决任务保护规则，普通日志不携带这些内容。

后台日志只包含固定事件、任务标识和安全错误描述，不包含密码、令牌、Cookie、验证码、完整页面或文章正文。管理员决定单独存储；日志接口按纯文本返回。日志查询默认最近 24 小时，每页 50 条、上限 100 条，单次时间范围不超过 31 天。

数据库任务日志保留 30 天。任务正文在满足终态、结果确定且不再需要恢复的条件下保留 30 天；正在执行、待登录、待核对或仍可安全重试的正文继续保留。管理员决定保留 90 天；任务摘要和远端关联保留供核对。具体清理规则由 [store.go](../apps/api/store.go) 定义。

本机进程日志位于私有状态目录，供启动故障检查，不由后台提供下载入口。应定期检查目录大小；生产环境需补充轮转、磁盘告警和备份策略。严禁上传真实登录页面、浏览器配置、私有日志或包含真实正文的截图。

## 参考方案

调研了 [Wechatsync](https://github.com/wechatsync/Wechatsync)（GPL-3.0）、[runningSherry/csdn](https://github.com/runningSherry/csdn)（未声明许可证）、[River](https://github.com/riverqueue/river)（MPL-2.0）和 [pg-boss](https://github.com/timgit/pg-boss)（MIT）。前两者包含私有签名接口或 Cookie 导入路径，本项目未复制其代码；后两者提供持久队列、唯一任务和恢复设计参考。

当前采用 Go 统一管理 PostgreSQL 任务与领取事务，Node 通过内部接口执行。单一任务状态便于统一账号互斥、未知结果核对及管理员处理；不同时引入第二套 Node 队列状态。平台操作使用官方网页及固定 Playwright 适配器，不调用模型猜测页面，也不复制私有接口签名逻辑。
